# Agent 特殊决策输出模式开发计划

> 状态：桌面端无概率 MVP 已实现，待运行态联调验收  
> 实施范围：桌面端（`src/`）；关联只读端 admAgent（`admAgent/`）未修改
> 参考模式：JEV 风格的 Choice / Noul / Score 决策输出

## 0. 实际实现（无概率 MVP，已落地）

> 本节描述当前代码的真实行为。第 4~8 节的请求字段、专用消息 part、自动判断策略与服务端依赖清单是**原提案，尚未实现**，不要据此找代码。

- **协议**：**P1 起输出契约由服务端负责**（`admAgent/internal/decision` + `internal/agent/decision_turn.go`，见 `doc/agent-decision-mode-server-plan.md`）。桌面端不再往 `prompt` 里拼控制块，只发送一个请求字段：

  ```json
  { "decision": { "mode": "auto|choice|bool|score", "tool_policy": "none", "structured_output": "auto" } }
  ```

  服务端把契约拼进**本轮系统提示词**（不落历史、不进标题、其它客户端看不到），走独立的单次决策轮：不注册工具、不做 nudge，只允许一次结果校验重定向重试，必须在回复里给出一个 `<adm_decision_result>{…}</adm_decision_result>` JSON 块（`choice`/`bool`/`score` 三种形状，整条回复只有它）。校验失败两次 → `run_complete.error = invalid decision output after 2 attempts: …`。

  > 旧会话（P1 之前）里正文仍带 `<adm_decision_request>` / `<adm_decision_contract>`，前端保留剥离与解析逻辑以便历史仍能画卡片。
- **渲染**：`decision_mode.js` 解析 **服务端专用 part**（`type=decision`，优先）或旧的正文结果标签，渲染 Choice / Bool / Score 卡片；未知 kind 折叠展示 `raw`。旧协议的控制块与结果标签在桌面端渲染前仍会剥离（`stripDecisionControlText`），轮标题与会话列表预览同样剥离。
- **只输出结果**：该轮一旦出现可解析的决策结果，assistant 侧只保留结果卡片——正文叙述、思考过程、工具调用/结果气泡全部不渲染（用户消息、轮标题、图片/附件不受影响）；**本轮运行期间就已隐藏**（不等到卡片出现，避免先闪过程输出再被卡片替换）；本轮跑完若始终没有有效结果，则回落为照常展示全部内容，便于排查模型违约。**整轮只渲染一张卡片**：模型在分步/重试里重复输出结果时，只取本轮最后一条带结果的消息；同一消息里出现多个结果块时也只取最后一个。契约中已明确要求"每个问题只输出一次结果块"。
- **模式持久化**：按 `workspace + session` 存 localStorage（`adm_agent_decision_modes_v1`），删除会话时清理；无会话时按钮禁用。
- **思考必须关闭**：选择任一决策模式会自动关闭模型思考（协议要求正文末尾即结果 JSON），"思考模式"勾选随之同步并持久化；**从决策模式切回普通对话时自动重新开启思考**（推理强度沿用设置里的档位）。同一模式内切换会话/工作区不改写用户自己的开关。
- **PDF 组合**：决策模式 + PDF 附件直接拒绝并提示，不进入分批流程。
- **模式集合**：可选四种决策模式 `auto` / `choice` / `bool` / `score`。原提案的 Noul 已被 Bool 取代，**不做兼容**：老会话里存的 `noul` 模式值回落为普通对话，历史消息里的 noul 结果不再解析成卡片。
- **结果校验**：`run_complete` 后若该轮为决策模式且历史中没有可解析的结果，提示"模型未返回有效的 Choice / Bool / Score 决策结果"，不自动重试。
- **已知限制**：
  1. 不提供任何概率/置信度（契约中明确禁止编造）。
  2. 决策轮不带工具：需证据的场景请先普通轮取证，再发决策轮。
  3. 结果标签的剥离以"该轮存在决策请求"为前提：若该轮用户消息缺失（压缩、外部注入），结果 JSON 会以原文显示。
  4. 结果已改为服务端专用 `decision` part 落库（P2），正文不再保留 JSON；TUI 等忽略未知 part 的客户端不会再看到裸 JSON（旧会话历史仍是标签）。
## 1. 目标

在 Agent 页面增加一个独立的“决策输出”模式。用户在输入问题后，系统先判断问题属于以下哪一种决策场景，再输出适合该场景的专用结果卡片：

| 决策类型 | 判断场景 | 目标输出 |
|---|---|---|
| Choice | 请求路由、工具/动作选择、分类、从多个候选中选择 | 选中项 + 候选清单（本版不提供概率分布） |
| Bool | 是/否条件判断、过滤、工作流门禁 | 布尔结论（成立/不成立）+ 依据 |
| Score | 质量评级、严重程度、优先级、连续程度评分 | 分数、归一化值、对应等级/标签 |

普通编码、问答、工具执行仍保留现有文本模式。提供四种决策模式：

- `text`：现有 Agent 对话模式，默认值。
- `decision-auto`：自动判断 Choice / Bool / Score，默认可选。
- `decision-choice`：用户明确指定 Choice。
- `decision-bool`：用户明确指定 Bool。
- `decision-score`：用户明确指定 Score。

其中 `decision-auto` 是“类 JEV”的主要体验；显式类型用于用户已知问题形态、需要固定输出协议的场景。

- part 签名位于 `src/views/agent/render.js:154-174`。
- part 渲染入口位于 `src/views/agent/render.js:836-987`。
- Rust SSE 事件为整体 JSON 透传，专用 part 原则上不需要增加事件白名单：`src-tauri/src/pages/agent.rs:2287-2377`。
- 当前模型能力仅有上下文、图像、推理等，没有结构化输出或概率能力字段。

### 底层能力结论（只读调研）

现有 admAgent 客户端支持工具参数 JSON Schema，可通过工具参数 `enum` 间接约束候选标签；但没有独立的分类结果、完整概率分布或期望值协议。`extra_body` 可透传结构化输出或 `logprobs` 请求字段，但当前响应解析会忽略 `logprobs`。

因此：

- 仅靠桌面端界面，无法可靠获得 JEV 式真实候选概率。
- 正式实现需要服务端提供“决策请求参数 + 决策结果 part + 可选概率”的协议。
- 若审核后坚持只改桌面端，可先实现无概率的结构化决策 MVP，但必须明确标注“概率不可用”，且不能保证所有模型稳定遵循 JSON；不建议作为最终方案。

## 4. 建议交互

### 4.1 输入工具栏

在模型选择器旁新增按钮：

```text
[模型 ▼] [输出：决策 ▼]
```

下拉项：

```text
普通对话
决策·自动判断
决策·选项选择
决策·无法判断
决策·评分
```

运行中保持当前轮模式只读；允许用户为下一轮预选模式，但不能用新模式修改已发出的请求。

### 4.2 决策配置

选择决策模式后，在输入框上方显示紧凑配置条：

- Choice：候选项列表、是否显示概率。
- Noul：可选“允许判断的条件”列表；缺省由模型生成简短原因。
- Score：最小值、最大值、是否使用离散等级。
- Auto：可先使用默认规则；候选项和评分范围为空时由模型提取。

建议保存粒度：**workspace 级默认 + session 级覆盖**。新建会话继承 workspace 默认，用户修改后只影响目标会话。

### 4.3 结果卡片

#### Choice

```text

置信状态  高 / 中 / 低 / 不可用

候选分布
请求审核       68.2%
直接执行       24.1%
取消           7.7%

概率必须来自服务端真实结果；字段缺失时隐藏概率条并显示“当前模型未提供概率”，不能由模型随意生成。

```

#### Score

```text

```

视觉沿用 Agent 现有暗色卡片、圆角和折叠交互；流式阶段显示骨架/加载态，完成后展示最终卡片。

## 5. 建议数据协议（原提案，未实现；现状见第 0 节）

### 5.1 请求参数

```json
{
  "session_id": "...",
  "prompt": "...",
  "run_id": "...",
  "decision": {
    "enabled": true,
    "mode": "auto",
    "choices": [
      { "value": "approve", "label": "批准" },
      { "value": "reject", "label": "拒绝" }
    ],
    "score": {
      "min": 0,
      "max": 10,
      "levels": [
        { "value": "low", "min": 0, "max": 3 },
        { "value": "medium", "min": 3, "max": 7 },
        { "value": "high", "min": 7, "max": 10 }
      ]
    },
    "allow_probabilities": true
  }
}
```

### 5.2 专用消息 part

Choice：

```json
{
  "type": "decision_choice",
  "data": {
    "selected": "approve",
    "label": "批准",
    "confidence": "high",
    "candidates": [
      { "value": "approve", "label": "批准", "probability": 0.682 },
      { "value": "reject", "label": "拒绝", "probability": 0.318 }
    ]
  }
}
```

Noul：

```json
{
  "type": "decision_noul",
  "data": {
    "reason": "缺少目标文件与验收标准",
    "missing_conditions": ["目标文件路径", "可接受的性能范围"]
  }
}
```

Score：

```json
{
  "type": "decision_score",
  "data": {
    "score": 8.3,
    "min": 0,
    "max": 10,
    "normalized": 0.83,
    "level": "high",
    "expected_value": 7.9,
    "distribution": []
  }
}
```

约束：概率建议使用 `0..1` 数值；评分必须位于 `[min, max]`；未知字段应被前端忽略；概率总和不足 1 时 UI 归一化展示但保留原始值用于调试。

## 6. 自动判断策略（原提案，未实现：当前由模型按契约自行判断类型，前端不改判）

`decision-auto` 建议采用“服务端路由 + 模型判断”两层策略：

1. 规则预判：
   - 问题明确要求从有限候选中选择、路由或执行动作 → Choice。
   - 缺少关键事实、条件不成立、无法验证或应拒绝猜测 → Noul。
   - 问题要求评级、严重度、优先级或连续量评估 → Score。
   - 同时出现多种意图时，以用户最终要消费的输出形态为准。
2. 模型结构化分类：规则不明确时，由模型返回 type、reason 和可选参数。
3. 前端只展示服务端确认的最终类型；允许用户切换/纠正类型后重新询问，不在渲染层自行改判。

优先级建议：`Noul 安全门 → Score 明确评分 → Choice 明确选择 → 模型分类兜底`。Noul 应防止模型在证据不足时强行输出 Choice 或 Score。

## 8. 服务端依赖清单（原提案，未实现；仅记录，不在本轮修改）

审核桌面端方案前需确认 admAgent 后续是否允许增加以下能力：

1. `POST /agent` 接收可选 `decision` 字段。
2. 决策模式使用专用工具或结构化输出约束，避免普通 Agent 自由发挥。
3. 消息协议允许三种 `decision_*` ContentPart，并支持 SSE 增量更新。
4. 概率字段只在模型真实返回时提供；不支持时返回 `probabilities_available: false`。
5. Noul 可作为明确终态，自动续跑、todos 完成检测不能把 Noul 当成失败。
6. `/messages` 历史接口完整保留决策 part。
7. 非法参数返回可读 400：空候选项、重复 value、min >= max、非法概率等。
8. 补充请求校验、流式合并、历史读取、模式自动判断和兼容降级测试。

## 9. 兼容与异常策略

| 场景 | 处理 |
|---|---|
| 普通模型未启用结构化输出 | 显示“当前模型不支持可靠决策输出”，自动退回普通文本模式 |
| 模型不支持概率 | 显示选中项/分数/原因，隐藏概率，明确“不可用” |
| 概率缺失或总和异常 | 不伪造数据；卡片标记“概率数据不完整” |
| 返回未知 decision part | 原始 JSON 折叠展示并记录调试日志 |
| Noul | 作为成功完成的明确结果，不自动续跑 |
| 用户中途切换模式 | 仅影响下一轮；当前轮使用请求发出时的快照 |
| 模型切换 | 重新校验能力；不兼容时回退普通模式并提示 |
| SSE 重连 | 通过消息历史恢复最终决策卡片，不重复提交决策 |
| 会话/工作区切换 | 按事件 `workspace_id` 隔离，不串卡 |
| 决策与工具执行同时出现 | 决策只展示建议；工具是否执行继续遵循现有权限系统 |

## 10. 验证计划

### 静态检查

- `pnpm typecheck`

### 手工用例

1. 普通模式回归：文本、思考、工具调用、附件、PDF 批次均不变。
2. Auto 三路：选择题、证据不足题、评分题分别命中正确类型。
3. 显式类型：强制 Choice / Noul / Score。
4. 概率缺失：卡片不显示虚假百分比。
5. 流式更新：候选概率或分数变化时实时刷新，完成后正确收口。
6. 历史恢复：刷新页面、切会话、workspace 切换后卡片一致。
7. Noul 终态：不触发自动续跑，不显示“任务未完整执行”。
8. 模型切换：不支持模型时正确禁用/回退。
9. 并发 workspace：A/B 两会话同时输出不同决策，不串 workspace。
10. 取消/排队/错误：沿用现有状态恢复逻辑，无残留 loading 卡片。

若不为本功能引入测试框架，则提供可重复的 fixture 演示页面或脚本进行协议联调。

## 11. 实施里程碑

### M0：协议确认

- 审核本文的交互、数据结构及 Noul 拼写。
- 确认是否必须显示真实概率。
- 确认决策配置按会话还是仅按 workspace 保存。
- 确认服务端协议排期；没有服务端支持时确定是否接受无概率 MVP。

### M1：桌面 UI 与本地状态

- 输出模式选择器、配置条、workspace/session 状态和模型切换兼容。
- 此阶段不发送真实决策参数，不展示模拟结果。

### M2：协议接入

- 请求参数、runStats、SSE、消息 part、历史恢复全链路接入。
- 明确拒绝伪造概率。

### M3：三类卡片

- Choice / Noul / Score 渲染、加载态、错误态、原始 JSON 兜底。
- 修复 Noul 与自动续跑/完成检测的冲突。

### M4：联调与回归

- 使用至少一个支持结构化输出的模型和一个普通模型验证能力降级。
- 执行类型检查和完整 Agent 页面回归。

## 12. 待审核决策

1. **Noul 名称**：图片与 JEV 资料中使用 `Noul`，是否按官方拼写保留；还是产品 UI 显示“无法判断”、协议内仍用 `noul`。
2. **是否允许无概率 MVP**：若 admAgent 暂时不改，建议先做结构化标签/分数卡片，但明确没有真实概率。
3. **Auto 判断范围**：只判断三類决策，还是普通问答也由模型先分类后再走 Agent。
4. **配置粒度**：推荐 workspace 默认 + session 覆盖；是否需要每个历史会话可修改。
5. **概率来源**：只接受模型 API 的原始概率，还是接受后续校准后的分数；本计划默认不接受模型自报“概率”。
6. **模式入口**：推荐输入栏常驻下拉；若希望减少工具栏占用，可改为设置弹窗 + 当前模式标签。
7. **执行联动**：第一阶段只给建议、不自动执行，还是允许选中项直接触发动作；推荐第一阶段只展示。

## 13. 推荐首批范围

建议先审核并实施 **M0 + M1 + 无概率结构化 MVP**：

- 自动判断 Choice / Noul / Score。
- 输出三张结果卡片。
- 不伪造概率。
- 不自动执行动作。
- 服务端概率与期望值能力待协议确认后接入。

这样能先验证交互和业务价值，同时避免桌面端自行拼装不可靠的 JEV 模拟结果。正式具备“完整候选概率分布 + 期望值”的版本，应在 admAgent 协议能力确认后作为第二阶段实施。
