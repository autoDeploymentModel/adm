# Agent 设置与云端模型（桌面端）

> 范围：`config.json` 里的 Agent 设置项、推理强度与思考开关的映射、云端模型 `can_reason` 约定，以及写入 admAgent.json 的开关链路（`/config/set` + `/agent/update`）。

---

## 设置项与开关写入链路

- **Agent 设置**：`agent_default_provider` / `agent_thinking_enabled` / `agent_reasoning_effort` / `agent_temperature` / `debug_logging` / `agent_allow_all_tools` 存储在 `config.json`（Settings 结构体），前端通过 `load_settings` / `save_settings` 读写。设置面板把思考开关与推理强度**合并为一个「推理强度」下拉**（`关闭 / low / medium / high`）：选「关闭」= `agent_thinking_enabled=false` → 发 `reasoning_effort: none`（保留原档位，切回具体强度即恢复），其余档位为 `agent_thinking_enabled=true` + 对应 effort；转换在 `utils.js` 的 `reasoningSettingValue` / `applyReasoningSetting`。桌面端与 admAgent 均固定 yolo（执行）模式：没有任何 Plan 模式开关，`/v1/workspaces/{id}/agent/mode` 端点已随 Plan 模式一并移除（**breaking change**：更早版本的 TUI 或第三方客户端调用该端点会收到 404，旧 TUI 的 `ctrl+y` 表现为静默无效；仓库内调用方仅桌面端 `ilink.rs` 与 TUI `workspace/client_workspace.go`，已同步更新）。
- **云端模型一律按「支持思考」写入**（桌面端 `add/edit_cloud_provider` + `src/views/agent/settings_dialog.js` 弹窗）：添加/修改云端模型的弹窗已去掉「支持思考模式」复选框，`can_reason` 恒为 `true`（同时写入 `reasoning_levels: ["low","medium","high"]` 与 `default_reasoning_effort: "medium"`，见 `src-tauri/src/pages/agent.rs:1333` / `:1553`）。**含义与边界**：`can_reason` 是能力总闸而非当轮档位——为 false 时服务端**永不**发送 `reasoning_effort`（`admAgent/internal/agent/coordinator.go:386`）；为 true 只是「允许发」，发不发仍由工具栏「推理强度」决定（选「关闭」→ 前端发 `reasoning_effort: none`（`utils.js:getRequestReasoningEffort`）→ `llm/client.go:204-219` 翻译为关闭思考，思考能力照样关掉）。因此**编辑既有非思考条目会把它静默升级为支持思考**（旧配置 `can_reason=false` 无法再通过弹窗保留）：对完全不接受 reasoning 参数的厂商，唯一退路是全局「推理强度=关闭」，而该路径本身会带 `reasoning_effort: none`，可能命中 `thinking_mode_unsupported` 400 并中断本轮；弹窗内已加只读提示说明该约定。若将来要恢复「零参数」能力，改法是编辑路径保留原条目的 `can_reason`、仅新增时默认 true。
- **开启所有工具调用**（Agent 设置→基础设置，`agent_allow_all_tools`）：开启后 `settings.rs` 调 `agent.rs` `sync_agent_allow_all_tools`，把 `options.bash_allow_all` 补丁进 admAgent.json → `POST /config/set`（磁盘全量重载）→ `POST /agent/update`（`UpdateModels` → `buildTools` 重建工具集）。**两个请求都必需**：config/set 只换配置对象，工具集是 buildTools 时构建的，少了 agent/update 开关不生效。admAgent 侧需支持 `options.bash_allow_all`（`internal/config` Options + `tools/bash.go` 的 `blockFuncs(allowAll)`），未支持的版本会静默忽略该字段（Go 不拒绝未知字段），开关表现为空转。Linux 上真正执行 sudo/apt 还需 `NOPASSWD` 免密（agent 进程无 TTY）。改动清单见 `doc/admAgent-patch-bash-allow-all.md`。
- **项目记忆入口与「压缩时自动提取记忆规则」开关**（桌面端 UI + admAgent `options.project_memory_sync`）：项目记忆不再放在 Agent 设置弹窗里，改由 toolbar「🧠 项目记忆」按钮（`id=agent-memory-btn`，紧邻「压缩上下文」）打开专用弹窗 `#agent-project-memory-overlay`（`src/views/agent/template.js` 标记 + `src/views/agent/memory.js` 的 `initProjectMemoryUI`/`openProjectMemoryDialog`/`refreshProjectMemory`；原 `settings_dialog.js` 里的 `initProjectMemoryUI` 已整体迁到 memory.js，`showSettings` 不再刷新记忆）。弹窗内的开关写入 config.json 的 `agent_project_memory_sync`（默认开：前端一律用 `!== false` 判定，见 `memory.js:memoryAutoExtractEnabled`；Rust 侧该字段是 `Option<bool>` + `skip_serializing_if`，**None = 未设置 = 开**——`Settings::default()` 的零值在 `save_agent_workdir` / `save_workdirs_internal` 等「首次写盘」路径里会被直接落盘，用 `bool` 会把「默认开」静默写成 `false`），`save_settings` 调 `agent.rs:sync_agent_project_memory`（`unwrap_or(true)`）→ `write_agent_option_bool("project_memory_sync", …)` 补丁 admAgent.json 的 `options.project_memory_sync` → `POST /config/set` → `POST /agent/update`（与 bash_allow_all 同一套流程）。admAgent 侧已支持该选项（`internal/config` 的 `Options.ProjectMemorySync *bool` → `coordinator.go` 传**闭包**（读活配置）→ `internal/context/manager.go` 的 `Manager.ProjectMemorySync func() bool`（nil = 开），压缩时实时求值，为 false 时跳过 `m.Project.Sync(...)`，**只停新增、不关注入**：`ProjectRender` 不受影响）。**必须用回调而不是快照 bool**：coordinator 只在构造时 `buildAgent` 一次（`coordinator.go:209`），之后 `run()` 走 `c.currentAgent.Run`、手动压缩走 `c.currentAgent.Summarize`，而 `/agent/update`（`UpdateModels`）只做 `SetModel`/`SetTools`、从不重建 `ctxMgr`——快照写法会把开关冻结到服务重启（实测：开关写入 `false` 且 `/config/set`+`/agent/update` 均 200 后，手动压缩仍在 11ms 内改写 `project_memory.json`）。改成读活配置的闭包后，`/config/set` 的 autoReload 一刷新即对下一次压缩生效，**不需要 `/agent/update`、也不需要重启**。改动清单见 `doc/admAgent-patch-project-memory-sync.md`。
